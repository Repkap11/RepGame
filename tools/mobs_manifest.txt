# One line per mob model:
# name|geo_file|geometry_id|skin1,skin2,...[|bone=rx,ry,rz;...]
# Paths are relative to $BEDROCK_SAMPLES (default
# bedrock-samples/resource_pack in this repo). The optional last field
# overrides bone rest rotations (degrees) where the rest pose comes from an
# animation file rather than the geo (the pig body's 90° setup rotation).
# `bone.cubes=` instead stores the rotation on the bone's own cubes only —
# for models authored with a pre-rotated cube under a transform hierarchy
# (the cat's vertical body slab, whose head/legs/tail are children). The
# textured box rotates at render time, so each face keeps its texels.
# `bone.move=dx,dy,dz` translates the bone's authored cubes and pivot and
# reparents it to the root — for Java-ported geometry whose bind layout
# relies on runtime pivot glue (the cat's tail2, authored detached behind
# tail1) or to tuck a part inside the body (the cat's front legs, whose
# authored tops poke 0.2 above the back). The bare token `cube_rot`
# instead honours each cube's geo `rotation`/`pivot` keys — for models
# that author their panels as rotated cubes (the minecart's bottom and
# walls) rather than pre-rotated geometry. Cube rotations are baked into
# MobCubeDef::rot about the bone pivot with a compensating origin shift;
# entries without the token keep ignoring cube rotations (the chicken
# body's geo rotation stays compensated by its `body=-90` override).
